# 性能调优实战

> **难度**: ⭐⭐⭐⭐⭐ | **重要程度**: ⭐⭐⭐⭐⭐

## 📚 概述

性能调优是一个系统工程，需要从多个层面进行优化。本文总结常见的性能问题和优化方案。

## 🎯 一、性能调优方法论

### 1.1 调优流程

```
1. 发现问题
   ├── 压测发现性能瓶颈
   ├── 生产环境监控告警
   └── 用户反馈响应慢

2. 定位问题
   ├── 分析监控数据
   ├── 查看日志
   └── 使用性能分析工具

3. 分析原因
   ├── CPU瓶颈
   ├── 内存瓶颈
   ├── IO瓶颈
   ├── 网络瓶颈
   └── 代码问题

4. 制定方案
   ├── 评估优化收益
   ├── 评估实施成本
   └── 制定回滚方案

5. 实施优化
   ├── 开发环境验证
   ├── 测试环境压测
   └── 生产环境灰度

6. 效果验证
   ├── 对比优化前后数据
   ├── 持续监控
   └── 总结经验
```

### 1.2 调优原则

#### 二八原则
```
80%的性能问题由20%的代码引起
优先优化热点代码
```

#### 先测量后优化
```
❌ 错误：凭感觉优化
✅ 正确：基于数据优化
```

#### 权衡取舍
```
性能 vs 可维护性
性能 vs 开发成本
性能 vs 资源成本
```

```bash
# 基础配置

-Xmx4g                    # 最大堆大小（建议与Xms相同）
-XX:MetaspaceSize=256m    # 元空间初始大小
-XX:MaxMetaspaceSize=512m # 元空间最大大小

# 新生代配置
-Xmn2g                    # 新生代大小（建议为堆的1/3到1/2）
-XX:SurvivorRatio=8       # Eden:Survivor = 8:1

# 大对象配置
-XX:PretenureSizeThreshold=1m  # 大于1M直接进入老年代
```

### 2.3 线程优化

#### 线程池配置

```java
/**
 * 线程池参数计算
 * 
 * CPU密集型：核心线程数 = CPU核数 + 1
 * IO密集型：核心线程数 = CPU核数 * 2
 * 混合型：核心线程数 = CPU核数 * (1 + 等待时间/计算时间)
 */
@Configuration
public class ThreadPoolConfig {
    
    @Bean("taskExecutor")
    public ThreadPoolTaskExecutor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        
        int corePoolSize = Runtime.getRuntime().availableProcessors();
        executor.setCorePoolSize(corePoolSize);
        executor.setMaxPoolSize(corePoolSize * 2);
        executor.setQueueCapacity(1000);
        executor.setKeepAliveSeconds(60);
        executor.setThreadNamePrefix("async-task-");
        
        // 拒绝策略：CallerRunsPolicy（调用者运行）
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        
        executor.initialize();
        return executor;
    }
}
```


## 🗄️ 三、数据库优化

### 3.1 SQL优化🔥

#### 慢查询定位

```sql
-- 开启慢查询日志
SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1;  -- 超过1秒的查询

-- 查看慢查询

```

#### 索引优化

```sql
-- ❌ 错误：没有索引
SELECT * FROM orders WHERE user_id = 123 AND status = 'PAID';

-- ✅ 正确：添加联合索引
CREATE INDEX idx_user_status ON orders(user_id, status);

-- 查看索引使用情况
EXPLAIN SELECT * FROM orders WHERE user_id = 123 AND status = 'PAID';
```

#### 避免全表扫描

```sql
-- ❌ 错误：使用函数导致索引失效
SELECT * FROM users WHERE DATE(created_at) = '2025-01-01';

-- ✅ 正确：使用范围查询
SELECT * FROM users 
WHERE created_at >= '2025-01-01 00:00:00' 
  AND created_at < '2025-01-02 00:00:00';

-- ❌ 错误：使用LIKE前缀模糊查询
SELECT * FROM products WHERE name LIKE '%手机%';

-- ✅ 正确：使用全文索引或ES
ALTER TABLE products ADD FULLTEXT INDEX idx_name(name);
SELECT * FROM products WHERE MATCH(name) AGAINST('手机');
```

#### 分页优化

```sql
-- ❌ 错误：深分页性能差
SELECT * FROM orders ORDER BY id LIMIT 100000, 20;

-- ✅ 正确：使用游标分页
SELECT * FROM orders WHERE id > 100000 ORDER BY id LIMIT 20;
```

public class DataSourceConfig {
    
    @Bean
    @ConfigurationProperties("spring.datasource.master")
    public DataSource masterDataSource() {

    }
    
    @Bean

        targetDataSources.put("master", master);

    }
}

## 🚀 四、缓存优化

### 4.1 Redis缓存策略🔥

#### 缓存穿透

```java
/**
 * 问题：查询不存在的数据，缓存和数据库都没有
 * 解决：布隆过滤器 + 缓存空值
 */
@Service
public class UserService {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Autowired
    private UserMapper userMapper;
    
    // 布隆过滤器
    private BloomFilter<Long> bloomFilter = BloomFilter.create(
        Funnels.longFunnel(), 
        10000000,  // 预期数据量
        0.01       // 误判率
    );
    
    public User getUser(Long userId) {
        // 1. 布隆过滤器判断
        if (!bloomFilter.mightContain(userId)) {
            return null;
        }
        
        // 2. 查询缓存
        String key = "user:" + userId;
        User user = (User) redisTemplate.opsForValue().get(key);
        if (user != null) {
            return user;
        }
        
        // 3. 查询数据库
        user = userMapper.selectById(userId);
        
        // 4. 缓存结果（包括空值）
        if (user != null) {
            redisTemplate.opsForValue().set(key, user, 1, TimeUnit.HOURS);
        } else {
            // 缓存空值，防止穿透
            redisTemplate.opsForValue().set(key, new User(), 5, TimeUnit.MINUTES);
        }
        
        return user;
    }
}
```

#### 缓存击穿

```java
/**
 * 问题：热点数据过期，大量请求打到数据库
 * 解决：互斥锁 + 永不过期
 */
public User getUserWithLock(Long userId) {
    String key = "user:" + userId;
    String lockKey = "lock:user:" + userId;
    
    // 1. 查询缓存
    User user = (User) redisTemplate.opsForValue().get(key);
    if (user != null) {
        return user;
    }
    
    // 2. 获取分布式锁
    Boolean locked = redisTemplate.opsForValue()
        .setIfAbsent(lockKey, "1", 10, TimeUnit.SECONDS);
    
    if (Boolean.TRUE.equals(locked)) {
        try {
            // 3. 双重检查
            user = (User) redisTemplate.opsForValue().get(key);
            if (user != null) {
                return user;
            }
            
            // 4. 查询数据库
            user = userMapper.selectById(userId);
            
            // 5. 写入缓存
            if (user != null) {
                redisTemplate.opsForValue().set(key, user, 1, TimeUnit.HOURS);
            }
            
            return user;
        } finally {
            // 6. 释放锁
            redisTemplate.delete(lockKey);
        }
    } else {
        // 等待后重试
        try {
            Thread.sleep(50);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        return getUserWithLock(userId);
    }
}
```

#### 缓存雪崩

```java
/**
 * 问题：大量缓存同时过期
 * 解决：过期时间加随机值 + 多级缓存
 */
public void setCache(String key, Object value) {
    // 基础过期时间 + 随机时间（0-300秒）
    long expireTime = 3600 + ThreadLocalRandom.current().nextInt(300);
    redisTemplate.opsForValue().set(key, value, expireTime, TimeUnit.SECONDS);
}

// 多级缓存
@Service
public class MultiLevelCacheService {
    
    // 本地缓存
    private Cache<String, User> localCache = Caffeine.newBuilder()
        .maximumSize(10000)
        .expireAfterWrite(5, TimeUnit.MINUTES)
        .build();
    
    public User getUser(Long userId) {
        String key = "user:" + userId;
        
        // 1. 查询本地缓存
        User user = localCache.getIfPresent(key);
        if (user != null) {
            return user;
        }
        
        // 2. 查询Redis
        user = (User) redisTemplate.opsForValue().get(key);
        if (user != null) {
            localCache.put(key, user);
            return user;
        }
        
        // 3. 查询数据库
        user = userMapper.selectById(userId);
        if (user != null) {
            localCache.put(key, user);
            redisTemplate.opsForValue().set(key, user, 1, TimeUnit.HOURS);
        }
        
        return user;
    }
}
```

### 4.2 缓存更新策略

```java
/**
 * Cache Aside Pattern（旁路缓存）
 */
@Service
public class CacheAsideService {
    
    // 读操作
    public User getUser(Long userId) {
        // 1. 先查缓存
        User user = getFromCache(userId);
        if (user != null) {
            return user;
        }
        
        // 2. 查数据库
        user = userMapper.selectById(userId);
        
        // 3. 写入缓存
        if (user != null) {
            setCache(userId, user);
        }
        
        return user;
    }
    
    // 写操作
    @Transactional
    public void updateUser(User user) {
        // 1. 先更新数据库
        userMapper.updateById(user);
        
        // 2. 删除缓存（而不是更新）
        deleteCache(user.getId());
    }
}
```


## 🔧 五、代码优化

### 5.1 常见性能问题🔥

#### 问题1：循环中创建对象

```java
// ❌ 错误：每次循环都创建StringBuilder
public String buildString(List<String> list) {
    String result = "";
    for (String item : list) {
        result += item;  // 每次都创建新的String对象
    }
    return result;
}

// ✅ 正确：使用StringBuilder
public String buildString(List<String> list) {
    StringBuilder sb = new StringBuilder();
    for (String item : list) {
        sb.append(item);
    }
    return sb.toString();
}
```

#### 问题2：N+1查询

```java
// ❌ 错误：N+1查询
public List<OrderVO> getOrders() {
    List<Order> orders = orderMapper.selectList(null);
    return orders.stream()
        .map(order -> {
            // 每个订单都查询一次用户信息
            User user = userMapper.selectById(order.getUserId());
            return convertToVO(order, user);
        })
        .collect(Collectors.toList());
}

// ✅ 正确：批量查询
public List<OrderVO> getOrders() {
    List<Order> orders = orderMapper.selectList(null);
    
    // 批量查询用户
    Set<Long> userIds = orders.stream()
        .map(Order::getUserId)
        .collect(Collectors.toSet());
    Map<Long, User> userMap = userMapper.selectBatchIds(userIds)
        .stream()
        .collect(Collectors.toMap(User::getId, u -> u));
    
    return orders.stream()
        .map(order -> convertToVO(order, userMap.get(order.getUserId())))
        .collect(Collectors.toList());
}
```

#### 问题3：大事务

```java
// ❌ 错误：大事务
@Transactional
public void processOrders(List<Order> orders) {
    for (Order order : orders) {
        // 处理订单
        orderService.process(order);
        
        // 发送通知（耗时操作）
        notificationService.send(order);
        
        // 更新库存
        inventoryService.update(order);
    }
}

// ✅ 正确：缩小事务范围
public void processOrders(List<Order> orders) {
    for (Order order : orders) {
        // 只在必要时使用事务
        processOrderInTransaction(order);
        
        // 异步发送通知
        asyncNotificationService.send(order);
    }
}

@Transactional
private void processOrderInTransaction(Order order) {
    orderService.process(order);
    inventoryService.update(order);
}
```

## ✨ 七、优化案例

### 案例1：接口响应时间从3s优化到300ms

**问题**：订单详情接口响应慢

**分析**：
1. N+1查询问题
2. 没有使用缓存
3. 查询了不必要的字段

**优化**：
1. 批量查询关联数据
2. 添加Redis缓存
3. 只查询必要字段

**效果**：响应时间从3s降到300ms

### 案例2：TPS从500提升到2000

**问题**：系统TPS上不去

**分析**：
1. 数据库连接池太小
2. 线程池配置不合理
3. 存在慢查询

**优化**：
1. 增加数据库连接池
2. 调整线程池参数
3. 优化SQL，添加索引

**效果**：TPS从500提升到2000
