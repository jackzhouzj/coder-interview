### 4. Review 评论规范

#### 好的评论示例 ✅

```python
# 评论 1：建设性建议
"""
💡 建议：这里可以使用列表推导式简化代码

当前代码：
result = []
for item in items:
    if item.status == 'active':
        result.append(item.name)

建议改为：
result = [item.name for item in items if item.status == 'active']

理由：更简洁，性能更好
"""

# 评论 2：指出潜在问题
"""
⚠️ 潜在问题：这里可能导致 SQL 注入

问题代码：
query = f"SELECT * FROM users WHERE name = '{name}'"

建议使用参数化查询：
query = "SELECT * FROM users WHERE name = %s"
cursor.execute(query, (name,))

参考：https://docs.python.org/3/library/sqlite3.html#sqlite3-placeholders
"""

# 评论 3：询问设计意图
"""
❓ 疑问：为什么这里使用同步调用而不是异步？

如果这个操作耗时较长，建议改为异步：
async def process_data():
    result = await fetch_data()
    return result

请确认是否有特殊原因需要同步调用。
"""
```

#### 不好的评论示例 ❌

```python
# 评论 1：过于主观
"这代码写得太烂了"  # ❌ 没有建设性

# 评论 2：没有说明原因

# 评论 3：过于琐碎
"这里少了一个空格"  # ❌ 应该用自动化工具检查
```

### 5. 自动化 Code Review

```python
# .github/workflows/code-review.yml
name: Code Review

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  code-quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      # 代码格式检查
      - name: Check code format
        run: |
          pip install black
          black --check .
      
      # 代码规范检查
      - name: Lint check
        run: |
          pip install flake8
          flake8 . --max-line-length=120
      
      # 类型检查
      - name: Type check
        run: |
          pip install mypy
          mypy .
      
      # 安全检查
      - name: Security check
        run: |
          pip install bandit
          bandit -r . -f json -o bandit-report.json
      
      # 测试覆盖率
      - name: Test coverage
        run: |
          pip install pytest pytest-cov
          pytest --cov=. --cov-report=xml
      
      # 上传报告
      - name: Upload coverage
        uses: codecov/codecov-action@v3
```

### 1. 文档类型

"""
用户登录接口

POST /api/auth/login

请求参数：
{
    "username": "string, 必填, 用户名或邮箱",
    "password": "string, 必填, 密码（6-20位）",
    "remember_me": "boolean, 可选, 是否记住登录状态"
}

响应示例：
成功（200）：
{
    "code": 0,
    "message": "登录成功",
    "data": {
        "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
        "user": {
            "id": 123,
            "username": "john_doe",
            "email": "john@example.com"
        }
    }
}

失败（401）：
{
    "code": 1001,
    "message": "用户名或密码错误"
}

错误码说明：
- 1001: 用户名或密码错误
- 1002: 账号已被锁定
- 1003: 验证码错误

@author erik.zhou
"""
```

#### 技术设计文档
```markdown
# 用户登录功能设计文档

## 1. 需求背景
用户需要通过用户名/邮箱 + 密码登录系统

## 2. 技术方案

### 2.1 认证方式
- 使用 JWT 进行身份认证
- Token 有效期：7天（remember_me=true）或 1天（默认）
- 支持 Token 刷新机制

### 2.2 安全措施
- 密码使用 bcrypt 加密（cost=12）
- 登录失败限制：5次/小时
- 支持验证码（失败3次后启用）
- 记录登录日志（IP、设备、时间）

### 2.3 数据库设计
```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    status TINYINT NOT NULL DEFAULT 1,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    INDEX idx_username (username),
    INDEX idx_email (email)
);

CREATE TABLE login_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    ip VARCHAR(45) NOT NULL,
    user_agent VARCHAR(255),
    status TINYINT NOT NULL,
    created_at DATETIME NOT NULL,
    INDEX idx_user_id (user_id),
    INDEX idx_created_at (created_at)
);
```

### 2.4 接口设计
见 API 文档

### 2.5 性能指标
- 响应时间：P95 < 200ms
- 并发支持：1000 QPS
- 可用性：99.9%

## 3. 风险评估
- 风险1：密码暴力破解 → 限流 + 验证码
- 风险2：Token 泄露 → 短期有效 + IP 绑定
- 风险3：数据库压力 → Redis 缓存 + 读写分离

## 4. 上线计划
- 开发时间：3天

- 灰度发布：10% → 50% → 100%
