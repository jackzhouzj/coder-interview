## 🎯 什么是火焰图

### 基本概念

火焰图（Flame Graph）是一种可视化性能分析工具，用于快速定位程序的性能瓶颈。

**火焰图的特点**：
- 📊 横轴表示样本数量或时间占比
- 📈 纵轴表示调用栈深度
- 🔥 颜色通常无特殊含义（只是为了区分）
- 🎯 宽度越大，表示该函数占用资源越多

### 火焰图类型

```
1. CPU火焰图
   - 分析CPU时间消耗
   - 定位计算密集型瓶颈
   
2. 内存火焰图
   - 分析内存分配
   - 定位内存泄漏和过度分配
   
3. Off-CPU火焰图
   - 分析等待时间
   - 定位IO、锁等待等问题
   
4. 差分火焰图
   - 对比优化前后差异
   - 验证优化效果
```

### 火焰图结构

```
main                                    [最宽，底部]
├── processRequest                      [次宽]
│   ├── parseJSON                       [中等宽度]
│   │   └── json.Unmarshal             [窄]
│   ├── queryDatabase                   [很宽，性能瓶颈！]
│   │   ├── sql.Query                  [宽]
│   │   └── rows.Scan                  [宽]
│   └── renderTemplate                  [窄]
└── handleError                         [很窄]
```


## 🔧 生成火焰图

### 方法1：使用pprof + go-torch

```bash

# 安装FlameGraph
git clone https://github.com/brendangregg/FlameGraph.git
export PATH=$PATH:$(pwd)/FlameGraph

# 生成CPU火焰图
go-torch -u http://localhost:6060/debug/pprof/profile -t 30

# 生成内存火焰图
go-torch -u http://localhost:6060/debug/pprof/heap --colors=mem
```

```bash
# 采集CPU profile

# 生成火焰图
go tool pprof -http=:8080 cpu.prof

# 采集内存profile
curl http://localhost:6060/debug/pprof/heap > mem.prof

# 生成内存火焰图
go tool pprof -http=:8080 mem.prof
```

### 方法3：在代码中生成

```go
package main

import (
    "os"
    "runtime/pprof"
    "time"
)

func main() {
    // 开启CPU profiling
    f, err := os.Create("cpu.prof")
    if err != nil {
        panic(err)
    }
    defer f.Close()
    
    if err := pprof.StartCPUProfile(f); err != nil {
        panic(err)
    }
    defer pprof.StopCPUProfile()
    
    // 执行业务逻辑
    runBusiness()
}

func runBusiness() {
    // 模拟业务逻辑
    for i := 0; i < 1000000; i++ {
        processData(i)
    }
}

func processData(n int) int {
    sum := 0
    for i := 0; i < n; i++ {
        sum += i
    }
    return sum
}
```

生成火焰图：
```bash
# 运行程序生成profile
go run main.go

# 生成火焰图
go tool pprof -http=:8080 cpu.prof
```

## 📊 CPU火焰图分析

### 案例1：HTTP服务性能分析

```go
package main

import (
    "encoding/json"
    "fmt"
    "log"
    "net/http"
    _ "net/http/pprof"
    "time"
)

type User struct {
    ID       int       `json:"id"`
    Name     string    `json:"name"`
    Email    string    `json:"email"`
    CreateAt time.Time `json:"create_at"`
}

// ❌ 未优化版本
func handlerBad(w http.ResponseWriter, r *http.Request) {
    users := make([]User, 0)
    
    // 模拟数据库查询（性能瓶颈）
    for i := 0; i < 10000; i++ {
        user := User{
            ID:       i,
            Name:     fmt.Sprintf("User%d", i),
            Email:    fmt.Sprintf("user%d@example.com", i),
            CreateAt: time.Now(),
        }
        users = append(users, user)
    }
    
    // JSON序列化
    data, _ := json.Marshal(users)
    w.Header().Set("Content-Type", "application/json")
    w.Write(data)
}

// ✅ 优化版本
func handlerGood(w http.ResponseWriter, r *http.Request) {
    // 预分配容量
    users := make([]User, 0, 10000)
    
    // 批量生成数据
    for i := 0; i < 10000; i++ {
        users = append(users, User{
            ID:       i,
            Name:     fmt.Sprintf("User%d", i),
            Email:    fmt.Sprintf("user%d@example.com", i),
            CreateAt: time.Now(),
        })
    }
    
    // 使用json.NewEncoder直接写入
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(users)
}

func main() {
    // 注册pprof handlers
    http.HandleFunc("/bad", handlerBad)
    http.HandleFunc("/good", handlerGood)
    
    log.Println("Server started at :6060")
    log.Fatal(http.ListenAndServe(":6060", nil))
}
```

**分析步骤**：

1. 启动服务并压测：
```bash
# 启动服务
go run main.go

# 压测
ab -n 1000 -c 10 http://localhost:6060/bad
```

2. 生成火焰图：
```bash
# 采集30秒的CPU profile
curl http://localhost:6060/debug/pprof/profile?seconds=30 > cpu.prof

# 查看火焰图
go tool pprof -http=:8080 cpu.prof
```

3. 火焰图分析结果：
```
main                                    [100%]
└── http.ListenAndServe                [99%]
    └── handlerBad                      [95%]
        ├── fmt.Sprintf                 [45%] ← 性能瓶颈1
        ├── append                      [30%] ← 性能瓶颈2
        └── json.Marshal                [20%] ← 性能瓶颈3
```

**优化建议**：
- 🔥 减少fmt.Sprintf调用，使用字符串拼接
- 🔥 预分配切片容量，避免动态扩容
- 🔥 使用json.NewEncoder直接写入，避免中间缓冲


### 案例2：数据处理性能分析

```go
package main

import (
    "fmt"
    "strings"
)

// ❌ 未优化版本
func processDataBad(data []string) string {
    result := ""
    for _, item := range data {
        // 字符串拼接（性能瓶颈）
        result += item + ","
    }
    return result
}

// ✅ 优化版本
func processDataGood(data []string) string {
    var builder strings.Builder
    // 预分配容量
    total := 0
    for _, item := range data {
        total += len(item) + 1
    }
    builder.Grow(total)
    
    for i, item := range data {
        builder.WriteString(item)
        if i < len(data)-1 {
            builder.WriteString(",")
        }
    }
    return builder.String()
}

func main() {
    data := make([]string, 10000)
    for i := range data {
        data[i] = fmt.Sprintf("item%d", i)
    }
    
    // 测试未优化版本
    _ = processDataBad(data)
    
    // 测试优化版本
    _ = processDataGood(data)
}
```

**火焰图分析**：

未优化版本：
```
processDataBad                          [100%]
└── runtime.concatstrings              [85%] ← 性能瓶颈
    ├── runtime.mallocgc               [50%]
    └── runtime.memmove                [35%]
```

优化版本：
```
processDataGood                         [100%]
└── strings.Builder.WriteString        [15%] ← 大幅优化
    └── runtime.growslice              [5%]
```

**性能对比**：
```
BenchmarkProcessDataBad-8     100    15000000 ns/op    500MB/op    10000 allocs/op
BenchmarkProcessDataGood-8    5000   300000 ns/op      1MB/op      1 allocs/op
```

性能提升：50倍，内存减少500倍

## 🧠 内存火焰图分析

### 案例3：内存分配分析

```go
package main

import (
    "fmt"
    "sync"
)

type Data struct {
    ID      int
    Content string
    Buffer  []byte
}

// ❌ 未优化版本 - 大量内存分配
func processWithoutPoolBad() {
    for i := 0; i < 10000; i++ {
        data := &Data{
            ID:      i,
            Content: fmt.Sprintf("Data%d", i),
            Buffer:  make([]byte, 4096),
        }
        // 处理数据
        _ = data
    }
}

// ✅ 优化版本 - 使用对象池
var dataPool = sync.Pool{
    New: func() interface{} {
        return &Data{
            Buffer: make([]byte, 4096),
        }
    },
}

func processWithPoolGood() {
    for i := 0; i < 10000; i++ {
        data := dataPool.Get().(*Data)
        data.ID = i
        data.Content = fmt.Sprintf("Data%d", i)
        
        // 处理数据
        
        // 归还对象池
        dataPool.Put(data)
    }
}

func main() {
    // 测试未优化版本
    processWithoutPoolBad()
    
    // 测试优化版本
    processWithPoolGood()
}
```

**内存火焰图分析**：

未优化版本：
```
processWithoutPoolBad                   [100%]
├── runtime.newobject                   [40%] ← 对象分配
├── runtime.makeslice                   [35%] ← 切片分配
└── fmt.Sprintf                         [25%] ← 字符串分配
```

优化版本：
```
processWithPoolGood                     [100%]
├── sync.Pool.Get                       [10%] ← 大幅减少
└── fmt.Sprintf                         [25%]
```

**内存对比**：
```
BenchmarkWithoutPool-8    1000    1500000 ns/op    80MB/op    30000 allocs/op
BenchmarkWithPool-8       5000    300000 ns/op     10MB/op    10000 allocs/op
```

内存减少：8倍，分配次数减少：3倍

### 案例4：内存泄漏检测

```go
package main

import (
    "fmt"
    "time"
)

// ❌ 内存泄漏 - goroutine泄漏
func leakyGoroutine() {
    ch := make(chan int)
    
    // 启动goroutine但永不退出
    go func() {
        for {
            select {
            case v := <-ch:
                fmt.Println(v)
            }
        }
    }()
    
    // ch永不关闭，goroutine永不退出
}

// ✅ 修复版本 - 使用context控制生命周期
func fixedGoroutine() {
    ch := make(chan int)
    done := make(chan struct{})
    
    go func() {
        defer close(done)
        for {
            select {
            case v := <-ch:
                fmt.Println(v)
            case <-done:
                return
            }
        }
    }()
    
    // 使用完毕后关闭
    time.Sleep(time.Second)
    close(done)
}

func main() {
    // 模拟内存泄漏
    for i := 0; i < 1000; i++ {
        leakyGoroutine()
    }
    
    // 等待观察内存增长
    time.Sleep(10 * time.Second)
}
```

**内存火焰图分析**：

泄漏版本（10秒后）：
```
runtime.goexit                          [100%]
└── leakyGoroutine.func1               [95%] ← 1000个goroutine
    └── runtime.chanrecv               [90%] ← 阻塞等待
```

**检测方法**：
```bash

curl http://localhost:6060/debug/pprof/heap > mem1.prof
```

## 🔍 差分火焰图

### 对比优化前后

```go
package main

import (
    "crypto/md5"
    "encoding/hex"
    "fmt"
)

// ❌ 优化前
func hashDataBefore(data []string) []string {
    result := make([]string, 0)
    for _, item := range data {
        hash := md5.Sum([]byte(item))
        result = append(result, hex.EncodeToString(hash[:]))
    }
    return result
}

// ✅ 优化后
func hashDataAfter(data []string) []string {
    result := make([]string, 0, len(data))  // 预分配
    hasher := md5.New()  // 复用hasher
    
    for _, item := range data {
        hasher.Reset()
        hasher.Write([]byte(item))
        result = append(result, hex.EncodeToString(hasher.Sum(nil)))
    }
    return result
}
```

**生成差分火焰图**：

```bash
# 采集优化前的profile
go test -bench=BenchmarkBefore -cpuprofile=before.prof

# 采集优化后的profile
go test -bench=BenchmarkAfter -cpuprofile=after.prof

# 生成差分火焰图
go tool pprof -base before.prof after.prof
```

**差分结果分析**：
```
函数                    优化前      优化后      差异
hashData               100%        100%        -
├── md5.Sum            45%         0%          -45% ✅
├── append             30%         5%          -25% ✅
└── md5.New            0%          15%         +15% ⚠️
```

**结论**：
- ✅ 消除了md5.Sum的重复创建（-45%）
- ✅ 预分配减少了append的开销（-25%）
- ⚠️ 增加了md5.New的调用，但总体性能提升60%

## 🎯 实战技巧

### 技巧1：识别热点函数

```
火焰图宽度 = 性能占比

宽度 > 50%  → 🔥 严重瓶颈，必须优化
宽度 30-50% → ⚠️ 重要瓶颈，建议优化
宽度 10-30% → 💡 次要瓶颈，可选优化
宽度 < 10%  → ✅ 正常，无需优化
```

### 技巧2：分析调用栈

```
深度很深（>10层）→ 可能存在递归或过度抽象
宽度很宽但深度浅 → 该函数本身是瓶颈
宽度很宽且深度深 → 子函数是瓶颈
```

### 技巧3：对比多次采样

```bash
# 采样3次，确保结果稳定
curl http://localhost:6060/debug/pprof/profile?seconds=30 > cpu1.prof
curl http://localhost:6060/debug/pprof/profile?seconds=30 > cpu2.prof
curl http://localhost:6060/debug/pprof/profile?seconds=30 > cpu3.prof

# 对比结果
go tool pprof cpu1.prof
go tool pprof cpu2.prof
go tool pprof cpu3.prof
```

### 技巧4：结合其他工具

```bash
# 1. 先用pprof top找出热点
go tool pprof cpu.prof
(pprof) top10

# 2. 再用火焰图可视化
go tool pprof -http=:8080 cpu.prof

# 3. 用list查看具体代码
(pprof) list functionName

# 4. 用benchmark验证优化
go test -bench=. -benchmem
```

### 实践2：定时采样

```go
package main

import (
    "fmt"
    "os"
    "runtime/pprof"
    "time"
)

// 定时采样CPU profile
func scheduledProfiling() {
    ticker := time.NewTicker(1 * time.Hour)
    defer ticker.Stop()
    
    for range ticker.C {
        filename := fmt.Sprintf("cpu-%s.prof", time.Now().Format("20060102-150405"))
        f, err := os.Create(filename)
        if err != nil {
            continue
        }
        
        pprof.StartCPUProfile(f)
        time.Sleep(30 * time.Second)  // 采样30秒
        pprof.StopCPUProfile()
        f.Close()
    }
}

func main() {
    go scheduledProfiling()
    
    // 业务逻辑
    select {}
}
```

### 实践3：压测场景

```go
package main

import (
    "fmt"
    "net/http"
    "sync"
    "time"
)

// 压测工具
func loadTest(url string, concurrency, requests int) {
    var wg sync.WaitGroup
    start := time.Now()
    
    for i := 0; i < concurrency; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            for j := 0; j < requests/concurrency; j++ {
                resp, err := http.Get(url)
                if err != nil {
                    continue
                }
                resp.Body.Close()
            }
        }()
    }
    
    wg.Wait()
    duration := time.Since(start)
    
    fmt.Printf("Completed %d requests in %v\n", requests, duration)
    fmt.Printf("QPS: %.2f\n", float64(requests)/duration.Seconds())
}

func main() {
    // 压测并采样
    go loadTest("http://localhost:8080/api", 100, 10000)
    
    // 等待压测开始
    time.Sleep(2 * time.Second)
    
    // 采样
    // curl http://localhost:6060/debug/pprof/profile?seconds=30 > cpu.prof
}
```

## ⚠️ 注意事项

### 1. 采样开销

```go
// ⚠️ CPU profiling有5%左右的性能开销
// 生产环境建议：
// - 短时间采样（30秒）
// - 低峰期采样
// - 采样频率不要太高

// ✅ 推荐做法
func safeProfiling() {
    // 只在需要时开启
    if needProfiling {
        startProfiling()
        time.Sleep(30 * time.Second)
        stopProfiling()
    }
}
```

### 2. 样本数量

```go
// ⚠️ 样本太少可能不准确
// 建议：
// - CPU profiling至少30秒
// - 高负载场景可以缩短到10秒
// - 低负载场景需要更长时间

// ✅ 检查样本数量
// go tool pprof cpu.prof
// (pprof) samples
// Total samples: 1000  ← 至少需要100+样本
```

### 3. 火焰图解读

```
⚠️ 常见误区：
1. 颜色深浅无意义（只是为了区分）
2. 横向位置无意义（按字母排序）
3. 只看宽度，不看绝对值

✅ 正确做法：
1. 关注宽度占比
2. 分析调用栈关系
3. 结合代码理解
4. 用benchmark验证
```

## 💡 总结

### 核心要点

1. **火焰图是可视化工具**
   - 横轴表示资源占比
   - 纵轴表示调用栈深度
   - 宽度越大，性能瓶颈越明显

2. **火焰图类型**
   - CPU火焰图：分析计算瓶颈
   - 内存火焰图：分析内存分配
   - Off-CPU火焰图：分析等待时间
   - 差分火焰图：对比优化效果

3. **分析技巧**
   - 识别宽度大的函数（热点）
   - 分析调用栈关系
   - 对比多次采样
   - 结合代码理解

4. **生产实践**
   - 独立端口提供pprof服务
   - 短时间采样（30秒）
   - 低峰期采样
   - 定时采样和监控

### 实践建议

1. **开发阶段**
   - 编写benchmark测试
   - 生成火焰图分析
   - 识别性能瓶颈
   - 优化热点代码

2. **测试阶段**
   - 压测场景采样
   - 对比优化前后
   - 验证优化效果
   - 回归测试

3. **生产阶段**
   - 在线采样分析
   - 定时采样监控
   - 问题排查定位
   - 持续优化

### 优化流程

```
1. 采样分析
   ↓
2. 识别热点
   ↓
3. 代码优化
   ↓
4. 验证效果
   ↓
5. 上线观察
```

### 常见优化方向

1. **减少内存分配**
   - 使用对象池
   - 预分配容量
   - 避免不必要的复制

2. **优化算法**
   - 选择更高效的算法
   - 减少不必要的计算
   - 使用缓存

3. **并发优化**
   - 合理使用goroutine
   - 避免锁竞争
   - 使用无锁数据结构

4. **IO优化**
   - 批量操作
   - 异步IO
   - 连接池

### 注意事项

⚠️ **采样开销**
- CPU profiling有5%左右开销
- 生产环境短时间采样
- 避免频繁采样

⚠️ **样本准确性**
- 至少采样30秒
- 高负载场景可缩短
- 多次采样对比

⚠️ **结果解读**
- 颜色无特殊含义
- 横向位置无意义
- 关注宽度占比
- 结合代码理解
