## 什么是火焰图

火焰图（Flame Graph）是一种可视化性能分析工具，用于快速定位程序的性能瓶颈。

### 核心特点

1. **直观可视化**：一眼看出热点函数
2. **层次结构**：展示函数调用栈
3. **宽度表示时间**：越宽表示占用时间越多
4. **颜色随机**：仅用于区分不同函数

### 火焰图结构

```
┌─────────────────────────────────────┐
│         main (100%)                 │  ← 最顶层
├──────────────┬──────────────────────┤
│ funcA (40%)  │   funcB (60%)        │  ← 中间层
├──────┬───────┼──────────┬───────────┤
│ f1   │  f2   │   f3     │    f4     │  ← 底层
└──────┴───────┴──────────┴───────────┘
```

## 火焰图类型

### 1. CPU 火焰图

分析 CPU 时间消耗

```go
import (
    "os"
    "runtime/pprof"
)

func main() {
    f, _ := os.Create("cpu.prof")
    defer f.Close()
    
    pprof.StartCPUProfile(f)
    defer pprof.StopCPUProfile()
    
    // 你的代码
    doWork()
}
```

### 2. 内存火焰图

分析内存分配

```go
import (
    "os"
    "runtime/pprof"
)

func main() {
    // 你的代码
    doWork()
    
    f, _ := os.Create("mem.prof")
    defer f.Close()
    
    pprof.WriteHeapProfile(f)
}
```

### 3. Goroutine 火焰图

分析协程状态

```go
import (
    "os"
    "runtime/pprof"
)

func main() {
    f, _ := os.Create("goroutine.prof")
    defer f.Close()
    
    pprof.Lookup("goroutine").WriteTo(f, 0)
}
```

### 4. 阻塞火焰图

分析阻塞操作

```go
import (
    "os"
    "runtime"
    "runtime/pprof"
)

func main() {
    runtime.SetBlockProfileRate(1)
    
    // 你的代码
    doWork()
    
    f, _ := os.Create("block.prof")
    defer f.Close()
    
    pprof.Lookup("block").WriteTo(f, 0)
}
```

## 读懂火焰图

### 基本规则

1. **Y 轴**：调用栈深度（从下到上）
2. **X 轴**：样本数量（不是时间顺序）
3. **宽度**：函数占用的时间比例
4. **颜色**：随机，无特殊含义

### 关键指标

```
┌─────────────────────────────────────┐
│  平台函数（runtime.*）              │  ← 系统调用
├─────────────────────────────────────┤
│  业务函数（main.*）                 │  ← 业务逻辑
├─────────────────────────────────────┤
│  底层函数（具体实现）               │  ← 热点代码
└─────────────────────────────────────┘
```

### 分析技巧

1. **找平顶**：宽而平的函数是热点
2. **看深度**：调用栈过深可能有问题
3. **观察比例**：占比超过 10% 需要关注
4. **对比优化前后**：验证优化效果

## 实战案例

### 案例 1：HTTP 服务性能优化

#### 问题代码

```go
package main

import (
    "encoding/json"
    "net/http"
    "time"
)

type User struct {
    ID   int    `json:"id"`
    Name string `json:"name"`
}

func handler(w http.ResponseWriter, r *http.Request) {
    // 模拟数据库查询
    time.Sleep(10 * time.Millisecond)
    
    users := make([]User, 1000)
    for i := 0; i < 1000; i++ {
        users[i] = User{ID: i, Name: "User" + string(rune(i))}
    }
    
    // JSON 序列化
    data, _ := json.Marshal(users)
    w.Write(data)
}

func main() {
    http.HandleFunc("/users", handler)
    http.ListenAndServe(":8080", nil)
}
```

#### 性能分析

```bash
# 1. 压测
go test -bench=BenchmarkHandler -cpuprofile=cpu.prof

# 2. 查看火焰图
go tool pprof -http=:8080 cpu.prof
```

#### 火焰图分析结果

```
发现热点：
1. json.Marshal 占用 45%
2. string 拼接占用 25%
3. time.Sleep 占用 20%
```

#### 优化代码

```go
package main

import (
    "encoding/json"
    "net/http"
    "strconv"
    "sync"
)

type User struct {
    ID   int    `json:"id"`
    Name string `json:"name"`
}

var (
    userPool = sync.Pool{
        New: func() interface{} {
            return &User{}
        },
    }
    
    // 预分配缓存
    cachedUsers []User
    cachedJSON  []byte
)

func init() {
    // 预生成数据
    cachedUsers = make([]User, 1000)
    for i := 0; i < 1000; i++ {
        cachedUsers[i] = User{
            ID:   i,
            Name: "User" + strconv.Itoa(i),  // 使用 strconv 代替 string()
        }
    }
    cachedJSON, _ = json.Marshal(cachedUsers)
}

func handlerOptimized(w http.ResponseWriter, r *http.Request) {
    // 直接返回缓存的 JSON
    w.Write(cachedJSON)
}

func main() {
    http.HandleFunc("/users", handlerOptimized)
    http.ListenAndServe(":8080", nil)
}
```

#### 优化效果

```
优化前：1000 req/s
优化后：15000 req/s
性能提升：15 倍
```

### 案例 2：数据处理性能优化

#### 问题代码

```go
package main

import "fmt"

func processData(data []int) []int {
    result := []int{}
    for _, v := range data {
        if v%2 == 0 {
            result = append(result, v*2)
        }
    }
    return result
}

func main() {
    data := make([]int, 1000000)
    for i := 0; i < 1000000; i++ {
        data[i] = i
    }
    
    result := processData(data)
    fmt.Println(len(result))
}
```

#### 火焰图分析

```
发现问题：
1. append 导致多次内存分配（60%）
2. 切片扩容占用大量时间（30%）
```

#### 优化代码

```go
package main

import (
    "fmt"
    "runtime"
    "sync"
)

func processDataOptimized(data []int) []int {
    // 预分配容量
    result := make([]int, 0, len(data)/2)
    
    for _, v := range data {
        if v%2 == 0 {
            result = append(result, v*2)
        }
    }
    return result
}

// 并发优化版本
func processDataConcurrent(data []int) []int {
    numCPU := runtime.NumCPU()
    chunkSize := len(data) / numCPU
    
    var wg sync.WaitGroup
    results := make([][]int, numCPU)
    
    for i := 0; i < numCPU; i++ {
        wg.Add(1)
        go func(idx int) {
            defer wg.Done()
            
            start := idx * chunkSize
            end := start + chunkSize
            if idx == numCPU-1 {
                end = len(data)
            }
            
            chunk := data[start:end]
            result := make([]int, 0, len(chunk)/2)
            
            for _, v := range chunk {
                if v%2 == 0 {
                    result = append(result, v*2)
                }
            }
            results[idx] = result
        }(i)
    }
    
    wg.Wait()
    
    // 合并结果
    totalSize := 0
    for _, r := range results {
        totalSize += len(r)
    }
    
    final := make([]int, 0, totalSize)
    for _, r := range results {
        final = append(final, r...)
    }
    
    return final
}

func main() {
    data := make([]int, 1000000)
    for i := 0; i < 1000000; i++ {
        data[i] = i
    }
    
    result := processDataConcurrent(data)
    fmt.Println(len(result))
}
```

#### 性能对比

```
原始版本：  500 ms
优化版本：  200 ms（预分配）
并发版本：   50 ms（8 核）
```

### 案例 3：内存泄漏排查

#### 问题代码

```go
package main

import (
    "time"
)

type Cache struct {
    data map[string][]byte
}

func (c *Cache) Set(key string, value []byte) {
    c.data[key] = value
}

func (c *Cache) Get(key string) []byte {
    return c.data[key]
}

func main() {
    cache := &Cache{data: make(map[string][]byte)}
    
    // 不断写入数据
    for i := 0; ; i++ {
        key := fmt.Sprintf("key_%d", i)
        value := make([]byte, 1024*1024)  // 1MB
        cache.Set(key, value)
        
        time.Sleep(10 * time.Millisecond)
    }
}
```

#### 内存火焰图分析

```bash
# 1. 运行程序并采集内存 profile
go run main.go &
PID=$!

# 2. 采集内存数据
curl http://localhost:6060/debug/pprof/heap > mem.prof

# 3. 查看火焰图
go tool pprof -http=:8080 mem.prof
```

#### 发现问题

```
内存持续增长：
1. map 无限增长（90%）
2. 没有过期机制
3. 没有容量限制
```

#### 优化代码

```go
package main

import (
    "container/list"
    "sync"
    "time"
)

type CacheItem struct {
    key       string
    value     []byte
    expiresAt time.Time
}

type LRUCache struct {
    capacity int
    items    map[string]*list.Element
    lru      *list.List
    mu       sync.RWMutex
}

func NewLRUCache(capacity int) *LRUCache {
    return &LRUCache{
        capacity: capacity,
        items:    make(map[string]*list.Element),
        lru:      list.New(),
    }
}

func (c *LRUCache) Set(key string, value []byte, ttl time.Duration) {
    c.mu.Lock()
    defer c.mu.Unlock()
    
    // 检查容量
    if c.lru.Len() >= c.capacity {
        // 删除最旧的元素
        oldest := c.lru.Back()
        if oldest != nil {
            c.lru.Remove(oldest)
            item := oldest.Value.(*CacheItem)
            delete(c.items, item.key)
        }
    }
    
    item := &CacheItem{
        key:       key,
        value:     value,
        expiresAt: time.Now().Add(ttl),
    }
    
    elem := c.lru.PushFront(item)
    c.items[key] = elem
}

func (c *LRUCache) Get(key string) []byte {
    c.mu.RLock()
    defer c.mu.RUnlock()
    
    elem, ok := c.items[key]
    if !ok {
        return nil
    }
    
    item := elem.Value.(*CacheItem)
    
    // 检查是否过期
    if time.Now().After(item.expiresAt) {
        c.mu.RUnlock()
        c.mu.Lock()
        c.lru.Remove(elem)
        delete(c.items, key)
        c.mu.Unlock()
        c.mu.RLock()
        return nil
    }
    
    // 移到前面（LRU）
    c.lru.MoveToFront(elem)
    return item.value
}

func main() {
    cache := NewLRUCache(1000)  // 限制 1000 个元素
    
    for i := 0; ; i++ {
        key := fmt.Sprintf("key_%d", i)
        value := make([]byte, 1024*1024)
        cache.Set(key, value, 5*time.Minute)
        
        time.Sleep(10 * time.Millisecond)
    }
}
```

## 优化技巧

### 1. CPU 优化

```go
// ❌ 频繁的字符串拼接
func concat(strs []string) string {
    result := ""
    for _, s := range strs {
        result += s
    }
    return result
}

// ✅ 使用 strings.Builder
func concatOptimized(strs []string) string {
    var builder strings.Builder
    for _, s := range strs {
        builder.WriteString(s)
    }
    return builder.String()
}
```

### 2. 内存优化

```go
// ❌ 频繁分配
func process() {
    for i := 0; i < 1000; i++ {
        data := make([]byte, 1024)
        // 处理 data
    }
}

// ✅ 复用缓冲区
var bufferPool = sync.Pool{
    New: func() interface{} {
        return make([]byte, 1024)
    },
}

func processOptimized() {
    for i := 0; i < 1000; i++ {
        data := bufferPool.Get().([]byte)
        // 处理 data
        bufferPool.Put(data)
    }
}
```

### 3. 并发优化

```go
// ❌ 串行处理
func processItems(items []Item) {
    for _, item := range items {
        process(item)
    }
}

// ✅ 并发处理
func processItemsConcurrent(items []Item) {
    var wg sync.WaitGroup
    sem := make(chan struct{}, runtime.NumCPU())
    
    for _, item := range items {
        wg.Add(1)
        go func(it Item) {
            defer wg.Done()
            sem <- struct{}{}
            defer func() { <-sem }()
            
            process(it)
        }(item)
    }
    
    wg.Wait()
}
```
